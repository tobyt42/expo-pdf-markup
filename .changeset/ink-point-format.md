Smaller, more portable ink in annotation sets, on iOS, Android and web.

- **Reading:** every platform now reads ink points in object form (`{"x": …, "y": …}`), array form (`[x, y]`) or a mix of both within one ink stroke. A malformed ink point, or an ink stroke that isn't an array, is skipped and the rest of the annotation set still loads (previously iOS and Android could reject the whole set, and web could draw `NaN`).
- **Writing:** ink coordinates are now rounded to the nearest 0.1 pt (at most one decimal digit, whole numbers without `.0`) and consecutive duplicate ink points within an ink stroke are dropped; a stroke that collapses to a single point is kept as two identical points so it still draws as a dot. This clean-up happens only when an annotation set is written, identically on every platform: ink points keep full precision while drawing and moving, and bounds and all other fields are written exactly as before. Ink points are still written in object form by default, but the coordinate values written will differ slightly from earlier releases. Loading an annotation set writes nothing and doesn't fire `onAnnotationsChanged`.
- **New `inkPointFormat` prop:** `'object'` (the default) or `'array'`, which makes ink-heavy annotation sets noticeably smaller; `version` stays at 1. Changing the prop doesn't write anything or fire `onAnnotationsChanged`; it applies from the next edit, when any annotation set loaded in either form is written in the chosen form. Only choose `'array'` once every version of your app that might read the annotation set includes this release or a later one, because earlier releases can't read array form.
- **New exports:** a platform-neutral `parseAnnotations(json)` helper, which reads either form and always returns ink points in object form (throwing on JSON that can't be parsed or has no `annotations` array), and the `AnnotationPointArray` and `InkPointFormat` types. `AnnotationPoint` and `InkAnnotation` are unchanged.
